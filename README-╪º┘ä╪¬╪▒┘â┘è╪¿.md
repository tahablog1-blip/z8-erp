# تحديث Z8 — نظام أوامر العمل (موظف الإعداد بوابة الكاشير)

## الرحلة الجديدة
```
حجز (باركود/يدوي) → queued → الكاميرا تقرأ اللوحة → preparing (أمر عمل مؤقت — مخفي عن الكاشير)
                                        ↓
                     موظف الإعداد: أصناف + خدمة + مراجعة البيانات والممشى
                                        ↓
                     "تأكيد وإرسال للكاشير" → ready → تظهر في نقطة البيع → invoiced
```

## الصلاحيات
الشاشة الجديدة بتظهر لأي موظف معه صلاحية **"تجهيز فاتورة وإرسالها للكاشير"** (`invoices.prepare`)
— فعّلها لموظف الإعداد من شاشة المستخدمين. الأدمن بيشوفها تلقائياً.

## نقاط مهمة
1. **السيارات القديمة/الحالية**: اتعبّت `ready` تلقائياً — بتفضل ظاهرة للكاشير زي ما هي، صفر تعطيل يوم التركيب.
2. **تطبيق الأندرويد**: مفيش أي تعديل مطلوب — الفلترة في الـAPI نفسه، فتطبيق POS هيشوف بس السيارات المؤكدة تلقائياً.
3. **اختيار العميل من الكشك** بيظهر لموظف الإعداد كمسودة جاهزة يعدل عليها ويأكدها.
4. **الخدمات بسعر يدوي**: موظف الإعداد يقدر يكتب سعر الخدمة يدوياً (بيتبعت priceVat للسيرفر).
5. لو عايز ترجّع النظام القديم مؤقتاً (كل السيارات تظهر للكاشير مباشرة):
   `UPDATE cars SET work_status='ready' WHERE work_status IN ('queued','preparing');`
   واقفل شاشة الإعداد بسحب الصلاحية — من غير أي تعديل كود.

## إصلاح v2 — "سجلت سيارة ما ظهرتش في الانتظار"
**السبب الجذري:** الموظف المربوط بفرع كان بيسجّل السيارة بفرع افتراضي غلط (أول فرع أبجدياً مش فرعه) —
السيارة بتتسجل فعلاً بس في فرع تاني، وقائمته مفلترة على فرعه فتختفي فوراً.

**الإصلاح (3 طبقات):**
1. الباك اند بيفرض فرع الموظف المربوط في التسجيل وبوابة الكاميرا مهما كان المبعوت (بيحمي الويب والأندرويد وأي عميل).
2. الواجهة بتفترض فرع المستخدم نفسه (7 مواضع اتصلحت).
3. اختيار الفرع في المودال بيتقفل على فرع الموظف المربوط.

**ملفان إضافيان:** `backend\app\modules\cars\api.py` (محدّث) + `frontend\src\app\(app)\cars\page.tsx`

**لو السيارة اللي سجلتها قبل الإصلاح عايز ترجّعها لفرعك، شغّل في psql:**
```sql
-- شوف هي راحت فين:
SELECT plate, customer_name, b.name AS branch, c.created_at
FROM cars c JOIN branches b ON b.id=c.branch_id
WHERE c.created_at > now() - interval '1 day' ORDER BY c.created_at DESC;
-- ورجّعها (بدّل القيمتين):
UPDATE cars SET branch_id='<uuid فرعك>' WHERE id='<uuid السيارة>';
```

## إصلاح v4 — الحل الجذري لـ"التسجيل مش بيظهر"
**التشخيص:** القراءة (SELECT *) بتنجح مهما كانت الأعمدة، لكن التسجيل (INSERT بأسماء أعمدة صريحة)
بيقع بـ500 لو قاعدة البيانات أقدم من الكود وناقصة أي عمود — وده بيبان في الواجهة كـ"سجلت وما ظهرتش".

**الحل من 3 طبقات:**
1. **تحصين ذاتي كامل عند الإقلاع**: إنشاء جدول cars كامل لو مش موجود + ALTER لكل عمود من 22 عمود
   (idempotent — آمن يتنفذ كل مرة) + جدول customer_vehicles (جراج العميل — كان ناقص وهيفجّر باركود الحجز)
   + جدول car_service_queue (طابور البوابة الذكية — كان بيتفحص من غير ما يتنشأ) + أعمدة customers.
2. **نهاية الفشل الصامت**: أي خطأ تسجيل بيطلع دلوقتي برسالة عربية بتقول العمود/الجدول الناقص بالاسم
   في الواجهة نفسها + سطر "✅ سيارة اتسجلت" في نافذة الباك اند عند كل نجاح.
3. إصلاحا v2 وv3 متضمنان.

**ملفان محدّثان:** `backend\app\main.py` + `backend\app\modules\cars\api.py`

**بعد النسخ:** أعد تشغيل الباك اند وراقب سطور "⚠ ensure-schema" لو ظهرت — وجرّب التسجيل:
إمّا هينجح وهتشوف "✅ سيارة اتسجلت"، أو هتشوف رسالة عربية بالسبب الحقيقي بالاسم.

## إصلاح v5 — الجذر النهائي لـ"بتتسجل وما تظهرش" (مثبت بالاختبار الحي)
اختبار API الحي أثبت: التسجيل بينجح 201 والقائمة بترجع 0 في نفس الثانية.
بالاستبعاد: عمود is_deleted موجود من العهد القديم بس nullable بدون default —
التسجيل بيسيبه NULL، وشرط is_deleted=FALSE في SQL بيطرد الـNULL،
فالسيارة بتختفي من 19 استعلام مرة واحدة.

**الحل:** تطبيع كل NULL → FALSE + فرض DEFAULT وNOT NULL عند كل إقلاع (idempotent)
+ نفس المعالجة لـcreated_at + تحصين COALESCE في الاستعلامين الرئيسيين.
**ملفان محدّثان:** `backend\app\main.py` + `backend\app\modules\cars\service.py`

بعد النسخ وإعادة التشغيل: سيارات TST بتاعة الاختبار (وأي تسجيلات قديمة مختفية) هتظهر فوراً.

## v6 النهائية — بعد حل أزمة "التسجيل يختفي" بالكامل
ملخص جذور المشكلة المكتشفة بالأدلة على مدار اليوم:
1. **عمود is_deleted كان nullable بدون default** (من العهد القديم) — قيم NULL كانت بتطرد
   السيارات من 19 استعلام. اتصلح بالتطبيع + DEFAULT + NOT NULL (بيتنفذ تلقائياً عند كل إقلاع).
2. **عملية باك اند قديمة معطوبة** كانت بتضيّع الكتابة رغم إرجاع 201 — ماتت مع إعادة التحميل
   وأصبح ثبات الكتابة مُتحققاً منه بالاختبار الحي.
3. إصلاحات مرافقة أثبتت نفسها: فرض فرع الموظف، line_workers → hr_employees،
   التحصين الذاتي الكامل للمخطط، رسائل خطأ عربية بدل 500 الغامضة.

هذه النسخة **نظيفة من كل إندبوينتات التشخيص المؤقتة** (debug-db / debug-write-test / debug-full-flow
اتشالت) — انسخها فوق المشروع مرة أخيرة حتى لو كل شيء يعمل، لضمان عدم بقاء أي مسار تشخيصي مفتوح.
